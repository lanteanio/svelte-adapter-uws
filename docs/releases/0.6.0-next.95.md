## Consumer changes

### Added: an app-driven topic epoch mint

Changing a topic's seq authority - counter to external allocator, partition to partition, a reset store - left client offsets pointing into a seq space that no longer continues them, with nothing repudiating them; `bumpTopicEpoch(topic)` now mints that topic a fresh generation so those offsets cold-rehydrate at their next resume.

- **Affects:** Apps whose topics change seq authority at runtime; every other topic keeps the process generation exactly as before.
- **Action:** None unless you change an authority - then call it on each worker where the change lands, since app code runs on every worker and the equality-only epoch repudiates old offsets everywhere identically.
- **Requires:** No new dependency or option.
- **Compatibility:** The subscribe ack and resume compares pick the minted value up through the same read authority `topicEpoch` wraps; the override rides the bounded per-topic map the relay-loss mint already uses. `createTestServer` and `vite dev` now answer per-topic epochs through the same shared module.
- **Engineering detail:** [Added for 0.6.0-next.95 in the complete changelog](../../CHANGELOG.md#060-next95---2026-08-26).

### Added: the send lanes take an explicit gap-fill `seq`

A resume hook replaying history had no way to put per-frame sequence numbers on what it sent; `options.seq` on `send` and `sendWire` now stamps the envelope and the binary frame's seq slot identically, side-effect-free - no counter advances, nothing recorded or captured.

- **Affects:** Resume hooks and replay backends doing gap-fill through the send lanes; every existing call is byte-identical without the option.
- **Action:** None to keep current behavior. Gap-fill replay passes each frame's stored seq: `platform.send(ws, topic, event, data, { seq })`.
- **Requires:** No new dependency or option.
- **Compatibility:** Number and bigint take the publish lanes' validation and safe-integer range; `false`/`null`/absent mean no seq; `true` throws, since the send lanes have no counter to draw. `sendWireBatch` deliberately takes no seq option - one value cannot be one-seq-per-entry; replay discrete frames through `sendWire`.
- **Engineering detail:** [Added for 0.6.0-next.95 in the complete changelog](../../CHANGELOG.md#060-next95---2026-08-26).

### Added: the static lane answers the full RFC 9110 precondition set

Mutable assets now serve `Last-Modified` beside the `ETag` and honor `If-Match` and `If-Unmodified-Since` with 412, `If-Modified-Since` with 304, and the list and `*` forms of both entity headers, evaluated in the RFC's order so a failed `If-Match` is never converted into a 304.

- **Affects:** Caches and clients revalidating static and prerendered responses; a cache that lost the ETag can now revalidate by date instead of re-downloading every full body.
- **Action:** None. Versioned immutable assets are unchanged - their filename is the validator and they carry neither header.
- **Requires:** No new dependency or option.
- **Compatibility:** Every request that answered 304 before still does; the new answers only add 304s and 412s where the RFC requires them. `If-Match` compares by opaque equality against any validator the lane issued, because every validator is weak by construction and strict strong comparison would refuse the exact tag the server handed out. `last-modified` joins the reserved `staticHeaders` keys, since the date preconditions answer from the file's real time.
- **Engineering detail:** [Added for 0.6.0-next.95 in the complete changelog](../../CHANGELOG.md#060-next95---2026-08-26).

### Changed: a subscription-drift report now says how many connections it summed and how many a close had already settled

A membership counted twice and a closed connection still in the live set produce the same sum, so the two quantities that separate them now ride on the report instead of being reconstructed by whoever reads it.

- **Affects:** Anyone reading `subs.total-mismatch` diagnostics; the two existing fields are unchanged and two more are added beside them.
- **Action:** None. A reader keying on `totalSubscriptions` and `summed` keeps working.
- **Requires:** No new dependency or option.
- **Compatibility:** Additive. `connections` is always present on a mismatch; `settled` appears only when the snapshot could answer, so an absent field means unmeasured rather than zero.
- **Engineering detail:** [Changed for 0.6.0-next.95 in the complete changelog](../../CHANGELOG.md#060-next95---2026-08-26).

### Changed: the `seq` publish option speaks one table, and refuses what it cannot carry

A value outside the contract - a numeric string, an object - now throws naming the legal forms instead of silently drawing the local counter, and an integer past the wire's safe-integer range throws instead of rounding; `{ seq: null }` means no seq, and `bigint` joins `number`.

- **Affects:** Callers passing seq values outside `boolean | number` - a numeric string from a JSON column was the typical accident - and, separately, callers passing an integer above `Number.MAX_SAFE_INTEGER`, such as a snowflake or a large Kafka offset, which previously published as a rounded value. Also `publishWireBatch` entries, where `true`, `false`, and `null` now act per entry as overrides of the shared options instead of falling through silently.
- **Action:** Pass a number or bigint for an explicit authority's value, `false` or `null` for no seq, `true` or nothing for the counter. A caller that relied on a non-contract value drawing the counter should say `true`. An authority whose ids run above the safe-integer range needs the wide id moved into the event data, or offset by a per-topic base, since `seq` now refuses it rather than rounding it.
- **Requires:** No new dependency or option.
- **Compatibility:** Absent, `true`, `false`, and in-range numbers behave exactly as before, on every lane and every surface (production, `createTestServer`, `vite dev`). `null` moves from counter to no-seq; non-contract values move from counter to `TypeError`. Two breaks to know about: an integer above `Number.MAX_SAFE_INTEGER` moves from a silently rounded publish to a `TypeError`, because the double seq space stops having a neighbour at distance one there and adjacent ids collapse onto one value, which stalls a client watermark that only advances on a strict greater-than.
- **Engineering detail:** [Changed for 0.6.0-next.95 in the complete changelog](../../CHANGELOG.md#060-next95---2026-08-26).

### Fixed: a `staticHeaders` value carrying a newline is refused at build time

A CR, LF or NUL in a configured value reached `res.writeHeader` verbatim, where it ends the header field and starts whatever follows - header injection, or a second response; names are now held to the RFC 9110 token grammar too.

- **Affects:** Builds configuring `staticHeaders`. A value or name that could split a response now fails the build instead of shipping.
- **Action:** None for a valid configuration. A build that starts failing was emitting a header a client could not have read correctly - remove the control character from the value, or correct a name that is not a bare HTTP token.
- **Requires:** No new dependency or option.
- **Compatibility:** Refused at build rather than sanitised at request time, so an operator is told rather than quietly served something other than what they configured. Every name the token grammar allows still passes, including the punctuation set, and names are lowercased as before.
- **Engineering detail:** [Fixed for 0.6.0-next.95 in the complete changelog](../../CHANGELOG.md#060-next95---2026-08-26).

### Fixed: a respawning worker is no longer quarantined for the relay backlog its boot could not drain

A crashed worker's replacement filled its ring while booting and the age ceiling read that as a stall, respawning it until the restart limit killed the process; the primary now skips a worker in the fan-out until it reports its reader live.

- **Affects:** Multi-worker deployments with the relay ring enabled, under enough relay traffic to fill a booting worker's ring inside its boot time.
- **Action:** None.
- **Requires:** No new dependency or option.
- **Compatibility:** Both ceilings and the `bytes`/`age` quarantine reasons are unchanged; what changed is that a booting worker is no longer handed frames to be judged on. A worker publishing into the relay before its siblings have attached reaches fewer of them, which the receiving worker already treated as a stream joined mid-flight rather than a lost frame.
- **Engineering detail:** [Fixed for 0.6.0-next.95 in the complete changelog](../../CHANGELOG.md#060-next95---2026-08-26).

### Fixed: a recover subscribe without a `ref` is refused loudly instead of dying silently

A subscribe asking for history could hit the saturated gate and get nothing back, leaving the client believing itself subscribed and resuming into a silent gap; it now gets `{"type":"error","code":"RECOVER_REQUIRES_REF"}` up front, on all three server surfaces.

- **Affects:** Hand-rolled clients only; the bundled client stamps a `ref` on every path, including the reconnect resubscribe batch.
- **Action:** Include a `ref` on any subscribe that carries `recover`. A `subscribe-batch` naming history in its recover map needs its one `ref` for the same reason.
- **Requires:** No new dependency or option.
- **Compatibility:** Plain ref-less subscribes keep their documented silence, and `recover` against a server with no resume hook stays ignored - there is no history to miss. The refusal engages only where the recover lane would.
- **Engineering detail:** [Fixed for 0.6.0-next.95 in the complete changelog](../../CHANGELOG.md#060-next95---2026-08-26).

### Fixed: the cursor plugin stops decoding and parsing frames the runtime already parsed

Its message hook now reads the pre-parsed envelope the adapter hands every hook, which also removes a per-message decoder allocation and a crash on a frame whose whole body is null.

- **Affects:** Every connection on a server with the cursor plugin installed, since that hook inspects each frame before the application's own handler sees it.
- **Action:** None.
- **Requires:** No new dependency or option.
- **Compatibility:** No wire or API change. Binary frames, frames over 8 KiB and anything the adapter did not pre-parse still take the decode path, which now shares one process-wide decoder.
- **Engineering detail:** [Fixed for 0.6.0-next.95 in the complete changelog](../../CHANGELOG.md#060-next95---2026-08-26).

### Fixed: the consistency auditor no longer reports a subscription drift that never happened

A connection whose native handle was freed while the auditor walked it was skipped from the window but still counted by the cap accountant, so the cross-check compared a complete counter against a short sum and reported a mismatch no membership explained.

- **Affects:** Deployments running the per-worker consistency auditor (`CONSISTENCY_AUDIT_INTERVAL_MS`) on a worker small enough for its whole population to fit one audit window; the rate tracked connection churn, so a busy worker reported more of them.
- **Action:** None. Re-read any `subs.total-mismatch` history against this fix before treating it as evidence.
- **Requires:** No new dependency or option.
- **Compatibility:** No wire, option, or metric name moved. A window that omits any connection now withholds the cap accountant instead of cross-checking against a partial sum, which is what a partial slice already did; a complete window still runs every check.
- **Engineering detail:** [Fixed for 0.6.0-next.95 in the complete changelog](../../CHANGELOG.md#060-next95---2026-08-26).

### Fixed: a batch call's `excludeWs` now excludes on both lanes

`publishWireBatch` honoured a call-level exclusion only for stateless codecs, so opting a codec into batch framing silently dropped it and the author heard its own updates back; the call-level socket now defaults every entry, and a per-entry `excludeWs` overrides it, on either lane.

- **Affects:** Callers passing `excludeWs` on `publishWireBatch`'s options with a stateful codec - previously ignored there without an error.
- **Action:** None. Per-entry exclusions behave exactly as before.
- **Requires:** No new dependency or option.
- **Compatibility:** The batch-level form is now documented on both surfaces; it was honoured undocumented on the stateless lane and ignored on the stateful one. An entry-level `null` exclusion now means absent (inherit the call-level default) on both lanes, where the stateless lane previously read it as an override to nothing.
- **Engineering detail:** [Fixed for 0.6.0-next.95 in the complete changelog](../../CHANGELOG.md#060-next95---2026-08-26).

### Fixed: the cluster relay's frame ceiling now measures encoded bytes

It compared UTF-16 string length, so a multibyte-heavy frame up to three times the configured size passed the sender and could land over every sibling worker's byte-measured backlog ceiling at once - the mass quarantine the ceiling exists to prevent.

- **Affects:** Multi-worker deployments that set `CLUSTER_RELAY_MAX_FRAME_KB` and relay non-ASCII payloads; ASCII payloads measured identically before and after.
- **Action:** None. A deployment relying on the old undercount to sneak larger multibyte frames through should raise the ceiling to the size it actually intends.
- **Requires:** No new dependency or option.
- **Compatibility:** Strictly tighter: encoded bytes are never fewer than code units, so nothing previously refused is now admitted. Refusal reports carry the exact encoded size.
- **Engineering detail:** [Fixed for 0.6.0-next.95 in the complete changelog](../../CHANGELOG.md#060-next95---2026-08-26).

### Fixed: a `seq` the wire cannot carry is refused even while an egress ceiling is shedding

The publish lanes validated the value as a side effect of stamping, which happens after the ceiling decides, so a bad `seq` came back as an ordinary-looking `false` under load and threw only once traffic dropped.

- **Affects:** Callers passing a `seq` outside the contract while an egress budget is armed. With no budget configured the refusal already arrived immediately and nothing changes.
- **Action:** None. The `TypeError` that now arrives on the offending call was always the correct answer; it was previously deferred to the first quiet window, pointing at a deploy that could be weeks old.
- **Requires:** No new dependency or option.
- **Compatibility:** The refusals, their messages and their classes are unchanged - only their timing is. A refused value charges no egress and advances no counter. `publishWireBatch` now takes the same decision at its call gate, so an empty batch refuses what a full one refuses, on production, `createTestServer` and `vite dev` alike.
- **Engineering detail:** [Fixed for 0.6.0-next.95 in the complete changelog](../../CHANGELOG.md#060-next95---2026-08-26).
