## Consumer changes

### Changed: a subscription-drift report now says how many connections it summed and how many a close had already settled

A membership counted twice and a closed connection still in the live set produce the same sum, so the two quantities that separate them now ride on the report instead of being reconstructed by whoever reads it.

- **Affects:** Anyone reading `subs.total-mismatch` diagnostics; the two existing fields are unchanged and two more are added beside them.
- **Action:** None. A reader keying on `totalSubscriptions` and `summed` keeps working.
- **Requires:** No new dependency or option.
- **Compatibility:** Additive. `connections` is always present on a mismatch; `settled` appears only when the snapshot could answer, so an absent field means unmeasured rather than zero.
- **Engineering detail:** [Changed for 0.6.0-next.95 in the complete changelog](../../CHANGELOG.md#060-next95---2026-08-26).

### Fixed: the cursor plugin stops decoding and parsing frames the runtime already parsed

Its message hook now reads the pre-parsed envelope the adapter hands every hook, which also removes a per-message decoder allocation and a crash on a frame whose whole body is null.

- **Affects:** Every connection on a server with the cursor plugin installed, since that hook inspects each frame before the application's own handler sees it.
- **Action:** None.
- **Requires:** No new dependency or option.
- **Compatibility:** No wire or API change. Binary frames, frames over 8 KiB and anything the adapter did not pre-parse still take the decode path, which now shares one process-wide decoder.
- **Engineering detail:** [Fixed for 0.6.0-next.95 in the complete changelog](../../CHANGELOG.md#060-next95---2026-08-26).

### Fixed: the consistency auditor no longer reports a subscription drift that never happened

A connection whose native handle was freed while the auditor walked it was skipped from the window but still counted by the cap accountant, so the cross-check compared a complete counter against a short sum and reported a mismatch no membership explained.

- **Affects:** Deployments running the per-worker consistency auditor (`CONSISTENCY_AUDIT_INTERVAL_MS`) on a worker small enough for its whole population to fit one audit window; the rate tracked connection churn, so a busy worker reported more of them.
- **Action:** None. Re-read any `subs.total-mismatch` history against this fix before treating it as evidence.
- **Requires:** No new dependency or option.
- **Compatibility:** No wire, option, or metric name moved. A window that omits any connection now withholds the cap accountant instead of cross-checking against a partial sum, which is what a partial slice already did; a complete window still runs every check.
- **Engineering detail:** [Fixed for 0.6.0-next.95 in the complete changelog](../../CHANGELOG.md#060-next95---2026-08-26).

### Fixed: the cluster relay's frame ceiling now measures encoded bytes

It compared UTF-16 string length, so a multibyte-heavy frame up to three times the configured size passed the sender and could land over every sibling worker's byte-measured backlog ceiling at once - the mass quarantine the ceiling exists to prevent.

- **Affects:** Multi-worker deployments that set `CLUSTER_RELAY_MAX_FRAME_KB` and relay non-ASCII payloads; ASCII payloads measured identically before and after.
- **Action:** None. A deployment relying on the old undercount to sneak larger multibyte frames through should raise the ceiling to the size it actually intends.
- **Requires:** No new dependency or option.
- **Compatibility:** Strictly tighter: encoded bytes are never fewer than code units, so nothing previously refused is now admitted. Refusal reports carry the exact encoded size.
- **Engineering detail:** [Fixed for 0.6.0-next.95 in the complete changelog](../../CHANGELOG.md#060-next95---2026-08-26).
